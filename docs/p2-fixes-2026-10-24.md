# P2 review fixes — 2026-10-24

This is a functional correction, separate from performance-only work. The user excluded the two P3 findings: extreme calendar-year timezone conversion and special extension keys in report catchall schemas. Those paths are unchanged.

## Identity collisions

Ordinary conversations and group chats now retain distinct source namespaces through parsing, current-branch filtering, date selection, conversation aggregates, attachment deduplication and attachment-month lookup. Source-less ancillary links resolve using the original conversation/message pair when possible. Only when that full pair, or a conversation-only reference, is ambiguous does the ordinary export namespace take precedence. The ambiguity index retains only referenced pairs and is built only for overlapping source IDs. Unscoped references without a conversation ID retain their existing match-any-selected-message behavior.

The parser's message/attachment key uses a source marker and a length-framed conversation ID. Different ID pairs containing NUL cannot collide. Overlapping-shard replacement, deletion and metadata enrichment use the same key. Public report IDs, report schema, stable ordering and original metadata remain unchanged; attachment and feedback source tags are internal to parsed data. Feedback counts distinguish two conversations sharing an ID when their message references identify different sources.

The corrected behavior is intentional for inputs that previously lost data: an ordinary current chain containing two messages and a group containing one message now reports three even if their conversation/message IDs overlap. A same-path attachment in each source remains two attachments. These cases are covered through the actual JSON/ZIP parser, local recalculation, saving and reopening.

## Warning totals and browser verification

Compact downloads increment the retained warning total rather than replacing it with the number of detail entries. This preserves v1 migration reports, which summarize original warnings without retaining each original detail. A valid v1 JSON just below 20 MiB exercises the real import → migration → compact download → reopen path: seven original warnings become eight after migration and nine after the compaction notice.

Playwright rejects a server already listening on port 4173, including locally. Its build/preview command therefore always runs for the tested source. A real occupied-port check confirms that test execution stops before any browser test body runs. Stop the existing preview before `npm run test:e2e`; CI retains its three-browser Pages gate.

## Validation

The pinned pre-optimization baseline and all its assertions remain unchanged. Nine new data tests protect the corrected cases; two browser cases exercise the real ZIP/worker/recalculation/persistence flow on both desktop and mobile. These tests protect authorized functional changes without rewriting the performance baseline.

The complete 510,000-message synthetic reports are compared with the retained `dc0f734` reports, ignoring only generation time, for UTC/all years and 2025/Asia/Shanghai. This checks every report field and array order, including previous-year comparison. Before/after timings are recorded for the same workload; no performance gain is claimed for these fixes.

Both complete reports matched. The all-years result retains 510,000 messages, 5,100 conversations and 25,000 attachments; the Shanghai 2025 result retains 354,100 messages, 3,541 conversations and 17,455 attachments. One before/after run measured import at 15.27/10.59 seconds and recalculation at 7.53/7.48 seconds. These individual runs do not isolate the patch's cost or establish a speedup; machine/cache variability still applies. No heap-memory improvement is claimed.
